# L3 子权重表验证计划

## 目标

判定 `score_numeric.js` 里 16 张按历史收益反向拟合的三级行业子权重表（`UTILITY_L3_WEIGHTS` / `BANK_L3_WEIGHTS` / `RESOURCE_L3_WEIGHTS` / `APPLIANCE_L3_WEIGHTS` / `EQUIP_L3_WEIGHTS` / `INSURANCE_L3_WEIGHTS` / `INFRA_L3_WEIGHTS` / `BROKER_L3_WEIGHTS` / `BRAND_L3_WEIGHTS`）**携带信号还是纯拟合噪声**，并据此决定去留。

这些表的注释明确写了拟合来源，例如：

- `国有大型银行`：「按近3年收益校准（农行>建行>工行>中行>邮储>交行）」
- `城商行`：「结构性限制：宁波无法靠线性权重登顶；取 ↔3y 最优（约80%）」
- `白酒`：「结构性限制：洋河无法靠线性权重大过汾酒」

拟合目标函数是 `rank_vs_return.js` 的 `exact / soft / miss` 与 `mean_rho`。每组只有 2~6 个观测点，却要定 11~13 个连续权重。

**先验判断**：用同样的 `percentileHigher` 分位函数 + 11 个维度 + 每组 200 套随机权重的搜索预算，**纯随机噪声标签**的冠军命中率是 n=2 时 99.3%、n=6 时 84.8%。代码注释自报的「约80%」低于噪声基线。本计划要做的是把这个先验判断变成用真实数据的、可复现的结论。

---

## 判定标准（必须在跑数之前锁定）

为避免事后找理由，三项检验的通过线一次性写死在这里。任何一项要改阈值，必须先改本文件并记录原因。

| 检验 | 指标 | 通过 | 存疑 | 失败 |
|---|---|---|---|---|
| 一・时间分割 | 检验期 `mean_rho` | ≥ 0.30 且 ≥ kind 基线 + 0.15 | 0.10 ~ 0.30 | < 0.10 或低于 kind 基线 |
| 一・时间分割 | 检验期 `exact` 率 | ≥ kind 基线 + 15pp | ±15pp 以内 | ≤ kind 基线 |
| 二・权重稳定性 | 两个半窗权重的余弦相似度 | ≥ 0.80 | 0.50 ~ 0.80 | < 0.50 |
| 二・权重稳定性 | leave-one-out 单维最大漂移 | ≤ 5pp | 5 ~ 15pp | > 15pp |
| 三・置换检验 | 置换 p 值 | ≤ 0.05 | 0.05 ~ 0.20 | > 0.20 |

**最关键的单一数字**：拟合后的 L3 权重在检验期是否跑得过**未经拟合的 kind 级默认权重**（`WEIGHTS.bank` / `WEIGHTS.utility` 等）。如果跑不过，L3 子表就是纯粹的负担——它增加了复杂度、降低了可解释性，却没有换来任何样本外的解释力。这一项优先于其它所有指标。

## 检验一：时间分割（样本外）

### 1.1 设计

| 期间 | 窗口 | 用途 |
|---|---|---|
| 拟合期 | 2022-08 → 2025-08（36 个月） | 当前 16 张表已经在这上面拟合过 |
| 检验期 | 2019-08 → 2022-08（36 个月，不重叠） | 从未参与拟合 |

对每个有 L3 子表的行业组，在**检验期**分别用三套权重算 `exact / soft / miss / rho`：

1. 拟合后的 L3 子表
2. 未拟合的 kind 级默认表（对照基线）
3. 等权（所有维度权重相同，作为下界参照）

### 1.2 前视偏差的处理

有个必须说清楚的问题：评分用的是**当前**事实卡（最新报告期财务、当前 PE/PB/TTM 股息率），拿它去解释 2019–2022 的收益，属于前视偏差。

但这个偏差的方向**对被检验方有利**——评分里含有 2022 年之后才存在的信息，理应更容易解释 2019–2022 的走势。所以：

- 如果检验期表现依然崩掉 → 结论是**决定性的**（连未来信息都救不了）。
- 如果检验期表现不错 → 结论**不能采信**，必须进 1.3 做干净版本。

### 1.3 干净版本（仅当 1.2 未能判定时才做）

重建 point-in-time 事实卡，把评分输入全部替换成 2022-08 时点可得的数据：

| 字段 | 可否复原 | 做法 |
|---|---|---|
| ROE / ROIC / 毛利率 / 净利 / OCF / capex | 可以 | F10 已抓多年年度序列，按报告期截断即可 |
| DPS 历史 / 派息率 / 分红纪律 | 可以 | `DIVIDEND_MAIN` 按实施公告日截断 |
| 不良 / 拨备 / 核充 / NIM / 偿付 / NBV | 可以 | `special.years` 按年度截断 |
| PE / PB / TTM 股息率 / 市值 | 可以但需重算 | 用当时的**未复权**月线收盘 × 当时股本，配当时年报的 EPS / BVPS / DPS 重算，不能用当前快照 |
| 应收周转 / 存货周转 / 合同负债 | 可以 | 同 `special.years` |

**注意**：重算 PE/PB 必须用未复权价格（或用后复权价格 + 同步后复权的每股指标，两者口径要一致）。直接拿后复权价除以当年 EPS 会得到无意义的数。

这一步工作量不小，所以放在条件分支里——先跑 1.2，多数情况下应该已经能判定。

### 1.4 交付

`~/Desktop/temp/l3_audit_test1_timesplit.json`，含每个 l3 组在两个期间、三套权重下的完整结果，以及汇总的 `mean_rho` / `exact` 率对比。

## 检验二：权重稳定性

如果一套权重反映的是真实的经济关系，那么轻微改变样本或时间窗，权重不该剧烈变化。

### 2.1 时间半分

把拟合期 36 个月切成 2022-08→2024-02 和 2024-02→2025-08 两个 18 个月窗口，各自**独立重新拟合**权重，然后比较：

- 权重向量余弦相似度
- 逐维同号率（有多少维度在两个半窗里都是「重要」或都是「可忽略」）
- top-3 权重维度的重叠数

这需要一个自动拟合器（见 3.1），因为原始权重是手工调的，无法复现调参路径。

### 2.2 Leave-one-out

对每个 l3 组，依次剔除一只票后重新拟合，记录每个维度权重的最大漂移。

n=2 的组直接跳过（去掉一只就没法比较了）——**这本身就是结论**。从各表注释里的校准靶标可以读出组内票数，其中 n=2 的有：

| 表 | 注释里的靶标 | n |
|---|---|---|
| `EQUIP_L3_WEIGHTS.轨交设备` | 通号>中车 | 2 |
| `APPLIANCE_L3_WEIGHTS.空调` | 美的>格力 | 2 |
| `RESOURCE_L3_WEIGHTS.铝` | 天山>南山 | 2 |
| `BANK_L3_WEIGHTS.农商行` | 渝农>沪农 | 2 |

这 4 张表用 12~13 个权重去拟合一个二元排序（1 比特信息），稳定性不可检验，应当直接下线而不必等其它检验。其余组按注释靶标是 3~6 只（`保险` 3、`证券` 3、`动力煤` 3、`基建市政工程` 3、`白酒` 5、`国有大型银行` 6），仍进入 leave-one-out。实际 n 以跑数时的 `score.peer.n` 为准，注释只作预判。

### 2.3 交付

`~/Desktop/temp/l3_audit_test2_stability.json`。重点看：`国有大型银行` 的 `asset: 0.33`、`高速公路` 的 `ocf_quality: 0.36`、`轨交设备` 的 `roic_durability: 0.35`、`动力煤` 的 `pb: 0.22` 这几个极端权重在扰动下是否还在同一量级。

## 检验三：置换检验

这是三项里最干净的——它不依赖任何关于"哪段时期有代表性"的假设，直接测量**拟合流程本身的容量**。

### 3.1 先实现自动拟合器

新建 `scripts/fit_weights.js`：

```
输入：facts JSON + 收益窗口 + 目标 l3 组 + 搜索预算 B
搜索：B 次 Dirichlet 随机采样权重单纯形，取目标函数最优者，再做坐标上升精修
目标：组内 exact 命中（主）+ Spearman rho（次，用于打破平局）
输出：拟合后的权重、样本内成绩、搜索轨迹
```

搜索预算 `B` 要标定到与手工调参可比。校准方法：调 `B` 使得**真实标签下的样本内成绩**接近代码注释自报的水平（银行组约 80%、多数组 exact），这样置换检验才是同一把尺子。把标定出来的 `B` 记录在案。

### 3.2 置换

对每个 l3 组：

1. 用真实收益标签跑 `fit_weights.js`，记录成绩 `S_real`
2. 把组内收益标签**随机打乱** 200 次（保持组结构和维度值不变，只打乱哪只票对应哪个收益），每次重新跑完整拟合流程，得到零分布 `{S_perm}`
3. p 值 = `count(S_perm ≥ S_real) / 200`

### 3.3 读数

`p > 0.20` 意味着：把收益标签换成随机噪声，拟合流程照样能达到同等或更好的成绩，那么原始拟合的"成功"不构成任何证据。

参照上面已经跑过的合成实验（11 维、200 次搜索、纯噪声标签）：n=2 时 99.3% 能命中冠军，n=6 时 84.8%。真实数据的维度之间存在相关性，容量会略低于这个上界，但预期仍然远高于代码自报的 80%。

### 3.4 交付

`~/Desktop/temp/l3_audit_test3_permutation.json`，逐组的 `S_real` / 零分布分位 / p 值。

## 决策

三项检验跑完后按下表处理，不允许"再调调看看"：

| 结果 | 处理 |
|---|---|
| 检验一失败（跑不过 kind 基线） | **下线全部 16 张 L3 子表**，`*WeightsForCard()` 一律返回 kind 级表 |
| 检验三 p > 0.20 | 同上，且在 SKILL.md 里明确禁止"按历史收益校准权重"这一做法 |
| 检验二失败但一、三通过 | 保留子表但强制收缩：`w_final = 0.5·w_L3 + 0.5·w_kind` |
| 三项全过（不预期发生） | 保留，但必须补齐 SKILL.md 的披露（现在 16 张表只披露了 4 张），并写明拟合窗口与样本 |

### 下线的具体改动

`score_numeric.js` 里 9 个 `*WeightsForCard()` 函数改为直接返回 kind 级表，L3 常量表保留但标记 `@deprecated` 并附本文件链接（保留证据，方便日后复盘）。

`--self-test` 里依赖 L3 权重的断言（`hydro-*`、`liquor-*`、`bank-*`、`appliance-*`、`infra-*` 等）需要同步更新期望值。**下线前先跑一遍 `node score_numeric.js --self-test` 记录当前基线**，改完再跑，逐条确认差异都是权重变化的预期后果，不是引入了新 bug。

### 与其它已知问题的关系

L3 子表下线后，n=2 时"每个维度只有 0 或 100 分"的问题会**更突出**（原来靠拟合权重掩盖了一部分）。所以下线应与分位收缩改造一起做：

```
score = w(n)·同行分位 + (1 − w(n))·kind级分位,  w(n) 随有效 n 递增
```

或者更简单直接：有效同行 `n < 4` 时不产生行业冠军、不给建仓建议，只输出事实卡。

## 执行顺序

1. **阶段 0**（数据 + 两个小改动）—— 阻塞后续全部工作
2. **检验三**（置换）—— 优先做，因为它不需要额外的历史数据，且结论最干净
3. **检验一**（时间分割）—— 需要 0.2 拉到的长月线
4. **检验二**（稳定性）—— 复用检验三实现的拟合器

如果检验三的 p 值就已经 > 0.20，一和二可以只作为补充证据快速跑一遍，不必深究干净版本（1.3）。

## 边界

本计划只判定 L3 子权重表的去留，不涉及其它已识别的问题（硬门槛缺绝对底线、银行替代红线未实现、`ncoIsBelowOne` 单位猜测、绝对估值闸门数值失效、布林与高股息策略的冲突、白酒合同负债与负债率方向、券商模板与策略目标不匹配等）。那些需要单独的计划。
