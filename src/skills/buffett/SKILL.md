# A股高股息长线复利策略执行框架

保守型高股息分析：股息可持续 + 可复现数字质地 + 技术位 → **今日建仓建议**（每行业技术到位最高分）。不做组合规划。

**原则**：**股息提供厚垫，质量看同类分位，布林决定何时动手，明显红线一票否决今日建议**。分红靠 FCF 覆盖（银行/保险/证券用专用表），不是账面利润；Boll 不进入质地分。今日名单 = 每个东财 `f100` 里**布林到位且无 hard 红线 / ⚠️** 的票中评分最高者；跨行业不比总分。现金 ≥20%；数字必须可追溯，缺口则暂停终评并不得入今日名单。

每步 **Run** 一行即可执行。flags / URL / 字段 / 完整串联 → [`references/eastmoney-data.md`](references/eastmoney-data.md)。执行前 `opencli doctor`。

**缓存目录**：一律写 [`~/Desktop/temp/`](file:///Users/zhengjiajun/Desktop/temp)（`buffettTmp()` 自动定位并创建），禁止默认写系统 `/tmp` 或仓库 `tmp/`。

**分工**：脚本抓数、硬筛、摊事实卡，并完成**全量数字评分**（同类分位；红线机械提示另算）。`gen_buffett_report.js` 只输出数字/技术/操作骨架；Agent 复核红线、**逐票撰写巴菲特交叉验证与主要风险**、完善桌面终报。经营壁垒可作不计分备注。禁止重打数字维、禁止手算总分、禁止把脚本分当红线终评。

```
Step0 原始 N → 全进 Step1 → 通过 M → 全量评分/红线
→ 对全部 M 只拉后复权 K 线并算布林
→ 前部：今日建仓建议（每个有技术建仓位的 f100 取最高分 1 只 + 无 hard 红线；可为 0；不设跨行业只数上限）；§2 个股全评覆盖全部 M 只
```

#### 数字维怎么打（脚本，Agent 不要重打）

主尺是**同一东财 f100 内的同类分位**（连续 0–100）。绝对值 knot、宽带宽夹段、自身过热帽**不再进入得分**；锚点仍打印在事实卡/报告里供阅读。明显红线（派息>100%、两年 FCF 盖不住分红、OCF 连续两年低于净利等）仍走 `red_hints`，不靠分数吞掉。

1. **同类**：仅同一东财 `f100`。有效样本 n≥2 才算分位；**n<2 无信息 → 该维给 50**（不是缺维）。同分用平均秩，全员相同约 50，不会变成 0。
2. **分位**：越高越好看「有多少同伴更差」；PB / 负债 / 不良 / DPS 下调次数 / 毛利率 σ / ROE CV 反过来。得分 = 分位四舍五入为 0–100 整数。
3. **绝对红线仍保留**：派息 >100% → 该维 0，并走红线。FCF 任一年 cover<1 → 该维最多 50。哨兵未核（派息/FCF 量级）→ 该维 —。
4. **持久性/趋势**同样改成分位：ROIC 用 5 年中位（越高越好）；毛利率用 5 年 σ（越低越好）；分红纪律用 DPS 下调次数（越少越好）；ROE 稳定性用 CV（越低越好）；偿付/投资收益趋势用两年变动（越高越好）；银行 NIM 用最新水平分位。
5. **总分由脚本直接给出**，禁止 Agent 改档或手算加权。🟢/🟡/🟠/🔴 按该票在本行业内的加权总分；复核 hard 红线属实则强制 🔴。
6. 本步不看 K 线、新闻。不要为打分去抓研报/一致预期。分红承诺卡上没有则不准编。

数字维不得人工推翻。哨兵或源数据有误时应修正/重抓后重新运行脚本，禁止在报告里手改档位或总分。

#### 行业锚（仅展示，不是得分公式）

行业唯一键是东财 `f100`（如「电力」「白酒」「银行」）。`anchors.approved.json` 仍用于报告「f100锚/标准值」列对照；**无该 f100 锚不再把该维打成 —**（分位不依赖锚）。事实卡必须打印锚版本与 f100。

##### 长期锚校准（低频维护，不是每次选股都跑）

1. `build_anchor_pool.js` 按 f100 选总市值靠前样本；默认每行业 20 家、市值 ≥200 亿、排除 ST/退市。
2. `calibrate_anchors.js --pool ... --resume` 抓近 10 个完整财年。每家公司至少 5 年有效值；先算公司长期中位/CV/σ，再算该 f100 横截面中位/分位。
3. 单项有效公司数 ≥2 才写入该 f100 候选；不足则该行业不出现在 candidate 中。输出 candidate JSON 与桌面 Markdown 复核报告，**不会自动改变评分**。
4. 人工复核报告后运行 `approve_anchors.js --candidate ... --yes`。日常评分只读 `anchors.approved.json`，并在结果中记录版本、f100 来源和 N。
5. **本阶段不抓、不校准 PB 历史**：报告里无 f100 PB 锚时仍可写类别软锚作对照，得分只看同类分位。

#### 权重表

银行现金流量表口径不同。**银行/保险/证券禁止用 FCF / 净现比**；银行/保险也不用负债率。保险用偿付，不要套银行不良率；证券用相对同业负债率，不要套工业杠杆线。

| 非银 | 银行 | 保险 | 证券 |
|---|---|---|---|
| FCF 覆盖 25% | 资产质量（不良/拨备）25% | 偿付充足 18% | ROE 稳定性 25% |
| 派息 14% | 核充率 `HXYJBCZL` 14% | 偿付趋势（近 2 年）8% | 派息 15% |
| ROE(3 年) 14% | 派息 15% | 派息 15% | ROE(3 年) 15% |
| PB 10% | ROE 10% | ROE(3 年) 18% | 分红纪律 10% |
| 负债率 10% | 净息差 10% | 投资收益 `NET_ROI` 趋势 10% | PB 10% |
| ROIC 持久性 10% | PB 10% | PB 10% | 负债率（相对证券锚）25% |
| 毛利率持久性 7% | 分红纪律 9% | 分红纪律 9% | |
| 分红纪律 10% | ROE 稳定性 7% | ROE 稳定性 12% | |

`fin_kind` **只认东财 f100**（银行 / 保险 / 证券|多元金融 / 其余=非金）。禁止用不良、拨备、核充、NIM、偿付、`NET_ROI` 有无来反推种类。

**派息**：>100% 该维 0，走红线。不再用健康带夹段否决 🟢。

##### 持久性维度（脚本机械评分）

1. **ROIC 持久性（非金融）**：近 5 年 ROIC 中位，在本 f100 内越高越好。不足 3 年该维缺失。
2. **毛利率持久性（非金融）**：近 5 年标准差，在本 f100 内越低越好。不足 3 年该维缺失。
3. **分红纪律（全类）**：从 `DIVIDEND_MAIN` 已实施方案解析「10派 X 元」，同一报告年度的中期/三季/年度分红相加为年度 DPS；禁止用 `MAINFINADATA.TOTAL_SHARE` 回推历史 DPS。相邻年度 DPS 下降 >5% 记一次下调；下调次数在本 f100 内越少越好。少于 3 年该维缺失。
4. **ROE 稳定性（银行/保险/证券）**：近 5 年 ROE 的 CV，在本 f100 内越低越好。不足 3 年该维缺失。
5. **金融 PB**：只看同类分位（越低越好）；报告可附 f100/类别软锚对照。当前校准阶段仍不抓 PB 历史。
6. **净息差（银行）**：最新净息差水平的同类分位（越高越好）。两年变动只作备注，不戴帽、不进得分。
7. **偿付充足（保险）**：综合偿付充足率的同类分位（越高越好）。
8. **偿付趋势（保险）**：两年百分点变动的同类分位（越高越好；行业一起降则大家分位接近）。

经营壁垒（牌照、资源、网络、转换成本、成本、品牌）只允许作为**不计分备注**，不得改变脚本总分、评级、排序或硬门槛结果。

**FCF** = 经营现金流 − 资本开支；覆盖率 = FCF / 年度分红。非金融单年覆盖 **>5 或 <-2** → 先复核单位，未复核不得落分。

**数据缺口**：任一计分维缺字段 → ⚠️，动作「数据缺口，暂停终评」。禁止用 50/60/75 凑分。今日建仓建议**排除** ⚠️ 与 hard 红线。

#### 红线（一票否决）

`red_hints`（hard）须复核后才能定 🔴；`soft_hints` 不自动一票否决（银行/保险/证券跳过现金流两条）：

1. 派息率 >100%——分支：
   - 净利同比腰斩 → hard「盈利骤降但分红维持」
   - 近两年 FCF 覆盖均 ≥1 → soft「特别分红倾向」（派息维仍 0，但不强制 🔴）
   - 任一年 cover<1 → hard「寅吃卯粮：FCF盖不住」
   - 无 cover → soft「须人工区分」（不自动否决）
2. 经营现金流连续 2 年 < 净利润（优先净现比 <1，否则 OCF<净利）——银行/保险/证券不适用；银行改用：不良率连续 2 年上升 且 拨备跌破 150%
3. FCF 连续 2 年 < 年度分红（cover<1）——银行/保险/证券不适用
4. 净利润亏损仍分红

**FCF 分红分母口径**：优先 `COMPRE.TOTAL_DIVIDEND`；若与「净利×派息」隐含值之比 <1/3，视 COMPRE 残缺改用隐含，并按年独立决策（禁止一年 COMPRE、一年隐含混用放大量级哨兵）。

**评级**（只看脚本总分 + hard 红线 + 缺口）：⚠️ 缺维不终评；🟢 ≥80；🟡 70–79；🟠 60–69；🔴 <60 或踩 **hard** 红线。`soft_hints`（如特别分红倾向）不自动 🔴。总分取自事实卡，禁止手算。

### Step 3：买卖点（仅布林；已删除估值分位次路径）

质地（Step 2）回答「质地如何」；**今日建仓建议** = 每个 `f100` 内、布林到位且无 hard 红线 / ⚠️ 的票中脚本总分最高者。跨行业不比总分。K 线与布林对**全部 M 只**都跑。

**禁止**：用股息率/PB 历史分位、`allow_batch`、`fetch_valuation_history.js` 给新建仓/分批/加仓仓位；禁止把「估值分位」写成信号来源。未到可尝试批量建仓条件 → 观望或持有（已持仓），§1 允许 K=0。

#### 3.1 后复权 K 线（强制）

必须用后复权收盘自算（`fqt=2` / `--adjust backward`）。禁止行情页默认 `fqt=1`、手抄布林。日/周 window=20、月 window=24，nbdev=2。报告必填 K 线来源。无后复权 K 线落盘不得写布林信号、不得给建仓/加仓。

Run（硬筛通过池全量，禁止按评级抽样）：
```bash
node scripts/fetch_kline_pool.js --pool ~/Desktop/temp/buffett_pass_pool.json --resume
```
单票调试仍可用 `fetch_kline_hfq.js` + `calc_bollinger.js`。flags 见 [`eastmoney-data.md`](references/eastmoney-data.md) §布林。

#### 3.2 多周期布林（唯一买卖路径）

带宽 = (上轨 − 下轨) / 中轨。带宽 **≥ 5%** 时按表执行；带宽 **<5%**、或 K 线不够算月线 24 期 → **观望**，不得用其它指标替代建仓。

| 区域 | 定义 | 动作 |
|---|---|---|
| 可尝试批量建仓 | **必须**月线中轨附近 + 日线中～下轨（含两端）。周线下轨附近为**更优、非必须** | 技术到位即写「建仓建议（布林技术到位）」——**含 🟡/🟠/🔴/⚠️、含 hard 红线**。同条件时周线也在下轨附近者优先。批量建仓后继续下跌、日线仍在中～下轨且月线仍满足中轨附近双条件，🟢 可可选加仓 |
| 持有区 | 月线在中轨上方，但未同时满足「半带宽 ≤0.25 且 股价偏离 ≤5%」 | 持有；禁止因「站上中轨」追涨加仓 |
| 减仓区 | 见 Step 4 | 按比例减仓 |

**月线中轨附近**（下半带只看带宽位置；略高中轨须**相对半带宽与股价 5% 同时成立**）：
- 位置 = 中轨以上用 `(收盘−中轨)/(上轨−中轨)`，中轨以下用 `(收盘−中轨)/(中轨−下轨)`；下轨=-1，中轨=0，上轨=+1
- 收盘在下半带（≤中轨，含跌破下轨）算到位
- 略高于中轨必须 **同时**：位置 ≤ 0.25（上半带 1/4）**且** `(收盘−中轨)/中轨 ≤ 5%`。窄带宽由 0.25 卡住（避免 5% 吞掉上半带）；宽带宽由 5% 封顶（避免 1/4 半带偏离过大）
- 任一条件不满足 → **持有区**，不得写建仓建议。禁止只用股价 5%，也禁止只用 0.25

**日线中～下轨**：下轨 ≤ 日线收盘 ≤ 中轨。  
**周线**：未到下轨附近仍允许写建仓建议，报告须标注「周线未到下轨」；到了则标注「周线共振」。

标注 **「信号来源：布林带」**。未到可尝试批量建仓条件 → 在 §2 写观望/持有，**不写建仓建议**（除非已持仓写持有/减仓）。布林到位但 hard 红线 / ⚠️ / 同业未居首 → 同样不写建仓建议，原因写在操作栏。

### Step 4：动作与仓位

| 布林 | 写入 | 禁止 |
|---|---|---|
| 技术到位且该行业到位候选中评分最高且无 hard/⚠️ | 写建仓建议，标明同业到位最高分+布林 | 持有区追涨加仓；hard 红线仍写建议 |
| 未到位，或同业已有更高分到位票，或 hard/⚠️ | 观望/持有/减仓（已持仓） | 用估值分位或其他指标凑建仓建议 |

**是否写新建仓建议** = 该 `f100` 内布林到位且无 hard/⚠️ 的票中脚本总分最高。必须等月线中轨附近 + 日线中～下轨；未到则观望。周线未到下轨也可写建议，同条件优先周线共振。每个有技术建仓位的行业各取 1 只，**不设跨行业只数上限**。

| 动作 | 百分比基数 |
|---|---|
| 批量建仓 / 加仓 / 目标仓位 / 现金 | **总资金** |
| 减仓 / 清仓部分 | **该票当前市值** |

单票上限建议 ≤15%（脚本总分 ≥90、无 hard 红线时可 20%，须备注）。

- **建仓建议**（该行业布林到位候选中评分最高 + 无 hard 红线）：最多 15%；周线下轨附近为更优，非硬门槛；本次操作写「建仓建议（同业到位最高分+布林）」
- **加仓**：仅 🟢；已有主路径仓；批量建仓后继续下跌、日线仍在中～下轨且月线仍满足中轨附近双条件（半带宽 ≤0.25 且 股价偏离 ≤5%）；单次 ≤8% 且 ≤已投入；禁止已进持有区后追涨加仓
- **减仓（布林）**：周中轨 1/10；周上轨 1/5；月上轨 1/3
- **清仓**：踩红线、FCF 捂不住分红、银行资产质量恶化、牌照/资源/商业模式等经营基础发生实质破坏

**今日预算**：新买/加仓合计 ≤ 总资金 30%；现金 ≥20%；无合格票则 K=0。每个有技术建仓位的 `f100` 取 1 只最高分（布林到位且无 hard/⚠️），**不截断**。未入今日名单者原因写在 §2 操作栏（布林结论 / 同业未居首 / hard 红线）。

**目标价**（操作采用技术档；后复权轨勿与未复权现价直接比绝对价）：
1. 近端 = 周中轨；乐观 = 周/月上轨中更保守者
2. 禁止为写「股息隐含价」去跑估值分位脚本；无可靠中枢则不编隐含价

税后股息：持股>1 年免税，否则按 10%/20% 提示。每票写下次检视时点。

## 避坑

- 跳过 Step 0 / 截断名单 / 失败改走 yjfp 或凭记忆凑池
- 未跑本步 Run 或未落盘就进下一步；不要在本文件扩写完整串联，flags 以 eastmoney-data.md 为准
- 用代码名单或简称（「电力」「酒」）归行业；必须用东财 `f100`
- DOM 扫表不校验「共 N 只」、或不按固定列+滚动列对齐
- 凭记忆填数字；派息不过哨兵；FCF 极端值不核单位；缺维用 50/60/75 凑分
- 重打数字维、手算总分，或用经营壁垒备注修改评分/排序
- 把 ROE/FCF/派息以其他名称重复加权，或仅按市值打分
- D 类数字维一律最高 80；或样本 <2 只仍给极端 0/100（应给 50）
- 把画像 ROE 中枢当精线（8.0% 上下差 1 档）
- 用 knot/夹段/过热帽改写脚本分位得分
- 用估值分位/`allow_batch`/股息隐含价给新建仓或「分批」；站上中轨追涨加仓；省略后复权
- 只给 🟢/🟡 拉 K 线、§2 对其余票写「未拉 K 线（非🟢/🟡）」
- 未到可尝试批量建仓条件仍凑今日建仓建议；仓位加总不留现金；hard 红线或 ⚠️ 仍写入今日建议；用跨行业总分截断今日名单
- 交叉验证套模板；脚本 `gen_buffett_report.js` 不得机械生成交叉验证/风险（须 Agent 现写）
